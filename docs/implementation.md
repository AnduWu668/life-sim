# 角色生活模拟：实现说明

在线版（带数据流图，可评论）：https://claude.ai/artifact/XTiTRsVgmp4z8YfApedrsH

## 概览

这是「角色生活模拟」的实现：导入一张角色卡，角色就一段一段地过下去，观看者用「故事走向」调整后面的生活。没有任何 npm 依赖，`npm start` 后打开 http://127.0.0.1:3000。

| 题目要求 | 怎么满足 |
| --- | --- |
| 1. 连续、一段段、100 段以上 | 每次只给模型「故事笔记 + 最近 3 段」，输入不随段数增长；周建国一条长线写了 105 段 |
| 2. 符合设定，走向可控 | 人设、性格、处境、世界书都进提示词 |
| 3. 故事走向起作用 | 走向拆成常驻的基调和一次性的事件；同一角色开两条线并排对比 |
| 4. 读起来有吸引力 | 小说、日记两种文体；提示词要求用事情演性格、生活有起有落、段尾留余味 |
| 5. 测试 3–5 个角色 | 3 张自写卡 + 2 张公开酒馆卡，共 6 条故事 |
| 6. 能交互演示 | 本地网页：导卡、下一段（流式）、连续写 N 段、停止、重写、改走向、看笔记、对比、导出 |

## 设计过程：先定术语，再写代码

动手前用两轮追问把方案定下来，19 个问题全部按推荐答案落地，只有模型从 DeepSeek 改成了火山方舟。术语记在 [CONTEXT.md](../CONTEXT.md)（15 个），方案记在 [plan.md](plan.md)。

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 项目位置 | 新建独立仓库 | 和分身电话无关，面试官能单独 clone |
| 形态 | 本地 Node 服务 + 一个网页，零依赖 | key 不进浏览器 |
| 观看者 | 不进故事；卡里的 `{{user}}` 变成一个普通配角 | 题目要的是角色自己的生活 |
| 一段 | 400–800 字，有标题和故事内时间 | 是生活片段，不是一天，也不是一条消息 |
| 故事走向 | 拆成基调和事件 | 「让她遇到旧情人」如果一直生效，会被反复写 |
| 连贯 | 故事笔记 + 最近 3 段 | 只给最近几段，写到第 30 段就会忘了第 3 段的人 |
| 存储 | 每个故事一个 JSON 文件 | 重启不丢，复制文件就是证据 |
| 生成操作 | 下一段、连续写 N 段、停止、重写最后一段 | 不做任意段回退，故事不分叉 |
| 文体 | 小说或日记，建故事时定下 | 只改提示词，不加界面 |
| 加分项 | 同一角色两条线并排对比 | 最直观地证明走向起作用 |
| 开篇 | 按人设重写，不照搬卡里的开场白 | 开场白是对 `{{user}}` 说的聊天句子 |
| 重写 | 沿用原段的事件，笔记从那段之前重新更新 | 重写是换个写法，不是当这件事没发生 |
| 语言 | 一律中文 | 公开卡大多是英文 |

## 整体结构

代码一共 6 个文件，没有框架和数据库。点一次「下一段」，请求这样走：

1. **网页**：点「下一段」发请求，边收边显示正文。
2. **server.js**：读出故事 JSON；同一故事同时只写一段。
3. **story.js 拼提示词**：人设 + 故事笔记 + 最近 3 段 + 基调、事件。
4. **方舟 pro · 写段**：流式输出 400–800 字，带标题和故事内时间；正文以 NDJSON 逐字推回网页。
5. **方舟 lite · 更新笔记**：旧笔记 + 新的一段，合成新的故事笔记。
6. **落盘**：两步都成功才写入，清空这段用掉的事件。

任何一步失败或被停止，这一段就整体作废，磁盘上的故事不变。角色卡只在建故事时解析一次，替换好宏后拷进故事 JSON，之后改卡不影响已有的故事。

| 文件 | 负责 |
| --- | --- |
| `server.js` | HTTP 接口，按故事加锁，读写 `data/stories/<id>.json` |
| `story.js` | 提示词、方舟调用、写一段与重写、导出 Markdown |
| `card.js` | 酒馆卡 PNG / JSON 解析，宏替换 |
| `public/index.html` | 整个页面：角色卡、故事、走向面板、对比视图 |
| `mock-ark.js`、`test.js` | 假方舟和 8 个测试 |

## 100 段以上怎么保持连贯

写第 N 段时，模型只看到四样东西，所以输入长度不随段数增长：

1. 人设：描述、性格、处境、世界书（截到 6000 字）、说话示例，以及只作参考的卡里开场白。
2. 故事笔记：当前故事内时间、人物和关系、地点、没收的线头、已发生的大事。
3. 最近 3 段原文。
4. 当前基调，以及这一段的事件（有的话）。

每写完一段，再用 lite 模型把「旧笔记 + 新的一段」合成新笔记。实测笔记稳定在 1000–2200 字，模型会周期性地压缩，不会一直涨。

时间推进靠三条规则：每段都是新的生活片段，和上一段通常隔几天到几周；同一个场景最多连写两段；提示里写明上一段的时间，要求往后跳。周建国 105 段从「11月12日」写到两年多后的「四月二十日」；最后一段里刘阿姨、张大爷、君子兰、沙枣酒都还接得上前文。

## 故事走向怎么起作用

走向分两种，管的时间长度不同，这是它能起作用、又不会把故事写死的关键。

- **基调**：标签（治愈 / 虐心 / 甜 / 冒险 / 悬疑 / 日常）加一句话，一直生效，直到改掉。决定后面故事的整体感觉。
- **事件**：「接下来发生…」，只管下一段，写完自动清空，不会被反复写。
- 每段都记下写它时用的基调和事件，页面和导出的 Markdown 里都看得到。
- 连续写的时候也能改走向：一段写完入库时，以磁盘上最新的走向为准，只清空刚被用掉的那条事件。
- 重写最后一段：基调用当前的；事件沿用原段的，填了新事件就用新的；故事笔记从那段之前的版本重新更新。
- 停止 = 断开连接，正在写的那段作废，什么都不存。

实测效果：林晚「治愈」和「虐心」两条线第 1 段都是「第三版提案被打回」，从第 2 段起分开：一边是深夜的热汤面、三角梅的邀约，另一边是涨租通知、空猫粮碗。周建国一条线中途换了三次走向，两个事件都准时写进了对应的段：第 26 段「刘阿姨突然住院」，第 51 段「女儿突然出现在家门口」。第 76 段起基调换成「一个人坐火车去老伴想去的地方」，第 77–80 段就是站台、列车和沙地。

## 角色卡导入

酒馆卡和自定义卡走同一条路：原文件存进 `cards/`，列表和建故事时再解析，统一成同一种结构。

- **PNG 酒馆卡**：读图片里的 tEXt 文本块，优先取 `ccv3`（V3），没有再取 `chara`（V2），base64 解出 JSON。不加依赖，十几行代码。
- **JSON 卡**：兼容 V1 旧字段（`char_name`、`char_persona` 等）和 V2/V3 的 `data` 结构。
- **世界书**：启用的条目整体并入人设，不做关键词触发。
- **宏替换**：`{{char}}`、`<BOT>` 换成角色名；`{{user}}`、`<USER>`（不分大小写）换成建故事时起的配角名。Seraphina 卡里那个被她救回来的旅人变成了「林舟」，Lara 卡里她暗恋的人变成了合作研究员「陈默」。
- **自定义卡**：页面表单生成一份 V2 JSON，和导入的卡走同一个接口。
- **安全**：上传限 10 MB，只收 .png / .json，文件名不能穿越目录；卡片内容只用 textContent 渲染，不进 innerHTML。

## 模型接入：火山方舟

沿用 master-app 的接法：直连方舟的 OpenAI 兼容接口，变量名也一样（`DOUBAO_API_KEY`、`ARK_BASE_URL`、`ARK_MODEL`）。

| 用途 | 模型 | 方式 |
| --- | --- | --- |
| 写段 | doubao-seed-2-0-pro-260215 | 流式输出，最多 2048 token |
| 更新故事笔记 | doubao-seed-2-0-lite-260215 | 非流式，最多 1500 token |

- 两个调用都关掉深度思考（`thinking: disabled`），只用按量计费的 `/api/v3`，不用 Coding Plan。
- 建连失败自动重试 2 次；单次请求 90 秒超时。
- 内容被拒、正文不到 100 字、中途断开，都算「写失败」：这一段不留、笔记不动，可以重试。
- 实测一段约 20 秒（写段加更新笔记）。

## 踩过的坑和修正

最大的一个坑是故事内时间不往前走，它让第一批约 140 段样例全部作废重跑。

| 现象 | 原因 | 修正 |
| --- | --- | --- |
| Seraphina 20 段全在「第 1 天·清晨」，周建国 36 段还在同一天 | 「段尾留钩子」加上最近 3 段原文，模型把每段都写成上一段的直接延续 | 每段换新片段、隔几天到几周、同场景最多两段；提示里带上一段的时间；旧样例作废重跑 |
| 英文卡的词漏进中文正文（glade、sundress） | 提示词只写了「用中文」 | 要求地名、物品等全部译成中文，人名可以保留 |
| 正文开头出现「<正文>」 | 模型抄了输出格式里的占位符 | 解析时去掉，加了测试 |
| 一批请求同时 fetch failed，或卡住十几分钟 | Mac 用电池时反复睡眠、断网 | 建连重试、超时从 180 秒降到 90 秒、批量用 caffeinate；合盖仍会睡 |
| 会话结束后网页打不开 | 服务是挂在会话下的后台进程 | 数据在磁盘上没丢，`npm start` 重启即可 |

## 已知局限与下一步

- **字数偏长**：周建国约一半的段（105 段里 52 段）超过 800 字；两张公开卡一段都没超。可以把 max_tokens 压低，或者超长就让模型缩写。
- **英文漏词**：英文卡仍偶尔漏出 healing、Shadowfangs、interdimensional 这类词。
- **笔记超长**：笔记实测 1000–2200 字，超过提示里写的 800 字上限，但不会一直涨。
- **高潮挤时间**：「冒险」「悬疑」基调到了剧情高潮，会把多段挤进一两天（Seraphina 第 9–20 段都在第 13–14 天）。
- **世界书**：只是整体截到 6000 字；条目多的卡该改成按关键词触发。
- **单机演示**：没有登录和多用户；同一个故事同一时间只能写一段。
- **公开卡**：两张公开卡不提交，README 只写来源链接。
